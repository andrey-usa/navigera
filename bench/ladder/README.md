# Browser-driver ladder

Head-to-head benchmark of CDP browser drivers on one scripted session,
run in CI (`.github/workflows/bench.yml`) on identical hardware.

## Contenders

| contender | driver | runtime |
|---|---|---|
| `nv-serve` | `navigera serve` — this repo (navigera + Chrome), the static musl build the releases ship | native, no Node |
| `nv-baseline` | the same, built the same way from `baseline_ref` (A/B, on request) | native, no Node |
| `nv-ws` | `nv-serve` over a DevTools WebSocket instead of the pipe | native, no Node |
| `nv-shell` / `nv-edge` / `nv-brave` / `nv-lightpanda` | `nv-serve` on chrome-headless-shell / Edge / Brave / Lightpanda | native, no Node |
| `playwright` | `playwright-core`, `channel: 'chrome'` | Node |
| `playwright-bun` | the same `playwright-core` script, run by Bun | Bun |
| `puppeteer` | `puppeteer-core`, system Chrome | Node |
| `chromiumoxide` | `chromiumoxide` 0.7 (bench-only crate in `contenders/`) | native Rust |
| `chromey` | `chromey` 2.x, maintained chromiumoxide fork (`contenders/`) | native Rust |
| `chromedp` | `chromedp` v0.19.1 (bench-only module in `contenders/`) | native Go |
| `gorod` | `go-rod` v0.116.2 (bench-only module in `contenders/`) | native Go |
| `gorod-shell` | the same go-rod build on chrome-headless-shell (`$SHELL_BIN`): `nv-shell`'s pair | native Go |

All drive the **same headless Chrome** (`--headless=new`) over the
**same fixture pages** (deterministic, generated by `gen_fixtures.py`,
served from 127.0.0.1 by a threaded server — no network weather, no bot
walls). Every contender's version (and the browsers') is recorded in
`publish.json` under `versions`.

One per-driver note: `go-rod`'s `Page.Eval` wraps the JS as
`function() { return (JS).apply(this, arguments) }`, so it invokes a bare
function expression itself — an explicit IIFE would break there (its
non-function result has no `.apply`). `gorod` therefore uses bare arrows,
which rod deterministically invokes; every other contender uses explicit
IIFEs for the same guarantee.

## The session (identical for every contender)

1. launch → 2. goto listing page → 3. eval title → 4. eval card count →
5. eval extract 500 cards as JSON → 6. fill search box → 7. click search →
8. eval visible-card count → 9. screenshot → 10. new tab → goto detail page →
11. eval title + row count → 12. close.

Plus two micros: **warm eval round-trip** (200× `() => document.title`) and
**cold start** (launch → new page → one eval → close).

**Agent tools** (`contenders/cli_agent.py`, scenario `agent`): the same
session the way an agent's tool calls drive it, one CLI process or one MCP
`tools/call` per step, plus one snapshot of the listing. Outside the
session's total, each tool also snapshots the 1000-row detail page, and
navigera starts a second session while the first one's shared browser is
still up (`start warm`). Snapshot sizes are each tool's default output,
what an agent reads. `navigera (batch)` runs the known steps in `batch`
calls as navigera's skill tells agents to; `navigera (own browser)` and
`navigera (baseline)` (with `baseline_ref`) are diagnostics.

**Matched operations** (`contenders/ops_agent.py`, scenario `ops`):
one call per op, warm session, median of 10 — the per-call table the README
quotes instead of the session's per-step mean. Ops, all on the listing page:
`goto`, `fill`, `click` (Search, no navigation), `click-submit` (the order
form's submit, handled by the page script, no navigation), `read-text`,
`snapshot`, `screenshot`, and `form-batch` (fill two fields, click submit,
read the status — one call for tools with a batch command, four calls
otherwise). Tools: navigera (plus `navigera (baseline)` with `baseline_ref`),
agent-browser, playwright-cli, Playwright MCP, Chrome DevTools MCP, and
browser-use's CLI (its exec model: one Python block per op against its own
throwaway Chrome; its snapshot comes from the documented raw `cdp()` route,
it has no built-in snapshot command). Each tool runs in its default output
mode (MCP tools over JSON-RPC, their only interface); no tool is switched
into a machine mode. Each op is verified after the call (same expected
value for every tool, verification untimed and outside the timed call for
every tool); a failed rep is recorded, not dropped, and a tool that cannot
run an op records why instead of a zero. Run in two rounds of 5 reps:
rounds are the outer loop and tools the inner loop, the second round in
reverse tool order. A cell is complete only with all 10 reps and no round
error; a partial cell keeps its samples in `publish.json` with
`incomplete: true`, is shown as `incomplete (n/N)` in the table, and is
left out of rankings, ratios and the losses page. Snapshot checks assert
the page's known heading and the Search button; screenshot checks fully
decode the PNG (chunk CRCs, IDAT decompression, exact raster size, every
scanline filter byte 0-4) and
assert its dimensions equal the session's live viewport, read untimed
(the tools run at different viewports, so no single size is asserted).

## Accounting

* **wall** — best of N, `perf_counter` around the run; `publish.json` also
  keeps every run and the median.
* **driver CPU / peak RSS** — the driver process's own `utime+stime`, read
  from its zombie's `/proc/<pid>/stat` before it is reaped, and its own
  VmHWM (the `navigera` binary for `nv-*`, node for the JS contenders).
  Not `wait4`: its rusage includes every child the driver reaped, Chrome
  included.
* **browser CPU / memory** — the whole browser process tree, sampled from
  `/proc` (CPU every 50 ms, PSS every 250 ms); approximate, marked `*`.
* **correctness** — every contender must produce identical normalized
  `extract_a.json` and identical counts (titles, card counts, filter result,
  row count); the ladder fails otherwise.

## Run it

```text
# from the repo root
python3 bench/ladder/gen_fixtures.py
# the released build: static musl (needs musl-tools and the rustup target)
cargo build --release --locked --bin navigera --target x86_64-unknown-linux-musl
cargo build --release --manifest-path bench/ladder/contenders/chromiumoxide/Cargo.toml
cd bench/ladder/contenders/chromedp && go mod tidy && go build -o ladder-chromedp . && cd ../..
cd bench/ladder/contenders/gorod && go mod tidy && go build -o ladder-gorod . && cd ../..
cd bench/ladder && npm install
NAVIGERA=$PWD/../../target/x86_64-unknown-linux-musl/release/navigera \
CHROME_BIN=$(which google-chrome) \
python3 ../ladder/ladder.py --out-dir out
```
